# Справжня 3D-змійка

Змійка в кубі 7³–15³ (за замовчуванням 13 × 13 × 13) на three.js (r128, `vendor/three.min.js`). Без збірки — відкрий `index.html` у браузері.

**Керування:** WASD / стрілки — горизонтально, E / Q — вгору / вниз, Space — пауза, R — заново, C — повернути камеру, L — таблиця рекордів, K — наступний скін, перетягування — обертання, коліщатко — масштаб.

Клавіші прив'язані до фізичних кнопок, тож працюють у будь-якій розкладці (англійська, українська тощо).

Натиск напрямку одразу робить крок: новий напрямок — миттєвий поворот, поточний — додатковий крок. Утримання клавіші поточного напрямку — прискорення (до ~3× швидше).

## Налаштування і рекорди

- Розмір поля (7, 9, 11, 13, 15) і складність обираються внизу; вибір запам'ятовується.
- Таблиця рекордів — топ-10 окремо для кожної пари «складність × розмір», зберігається в `localStorage` браузера. Відкривається кнопкою з кубком, клавішею L або з меню паузи / кінця гри.

## Скіни

Класичний, Red Dragon (темно-червона луска, роги, шипи на спині, очі з вертикальною зіницею, вогняні іскри), Frost (крижаний градієнт і кристали), Tiger (смуги, вушка) і Neon (веселка). Вибір — у списку внизу або клавішею K, працює і під час гри; запам'ятовується разом з іншими налаштуваннями. Кольори сегментів — instance colors того ж InstancedMesh, шипи — ще один InstancedMesh (+1 draw call лише для скінів із шипами).

Тіло й голова мають процедурні фактури (луска, лід із тріщинами, хутро, неонова схема): канвас 256 px, що тайлиться, генерується один раз на скін і використовується як `map` і `bumpMap`. Дракон періодично і після кожного яблука дихає вогнем із пащі: пул частинок `THREE.Points` з адитивним свіченням (1 draw call) плюс точкове світло, що підсвічує голову. Частинки живуть у фіксованих буферах без алокацій за кадр.

## Оптимізації швидкодії

- Тіло змійки — один `InstancedMesh` замість окремого меша на кожен сегмент: draw calls не ростуть із довжиною (було `довжина + ~20`, стало 16 сталих).
- Сітка зайнятості `Uint8Array(N³)`: перевірка самоукусу O(1), пошук вільної клітинки без рядків і `Set`.
- Інтерполяція руху без копіювання всієї змійки щотіку (зберігається лише старий хвіст).
- Пул частинок: меші й матеріали створюються один раз.
- HUD: закешовані DOM-вузли, текст пишеться лише при зміні.
- Лінія-підказка до яблука оновлюється тільки при його переміщенні.
- Під меню (пауза / старт / кінець гри) з нерухомою камерою кадр не перемальовується.
- Прибрано `backdrop-filter` з HUD-бейджів над WebGL-полотном.
- Адаптивна роздільність: при стабільно повільних кадрах `pixelRatio` знижується (не нижче 1) і повертається, коли стає швидко.

## UI-тести

[Playwright Test](https://playwright.dev), Chromium з програмним WebGL (SwiftShader), тож пікселі не залежать від GPU.

```bash
npm install
npx playwright install chromium   # один раз
npm test                          # усі тести
npm run test:update               # перезаписати еталонні скриншоти після свідомих візуальних змін
SLOWMO=500 npx playwright test --headed --workers=1   # видимий браузер, пауза між діями
npx playwright test --ui          # UI mode: кроки, знімки DOM, запуск окремих тестів
```

- Тести відкривають `index.html?test`. Параметр `?test` вмикає хук `window.__snake`: стан гри лише для читання (зокрема `size`) і `setFood()`. Без параметра хука немає.
- Час гри тестує фейковий годинник `page.clock`, тож кроки змійки детерміновані. `Math.random` у тестах із фіксованим seed.
- Еталонні скриншоти (`tests/visual.spec.mjs-snapshots/*-darwin.png`) прив'язані до macOS. На іншій ОС їх треба згенерувати окремо. Допуск — 300 пікселів: між прогонами фаза кадру фейкового годинника зсуває змійку на частку клітинки (до ~140 пікселів), а зсув яблука на одну клітинку дає ~445.
- Скриншоти з програмним WebGL повільні: на слабшій машині може знадобитися менше воркерів (`npx playwright test --workers=2`).
